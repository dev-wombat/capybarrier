# CapyBarrier 릴리스 검증 기준

## 통과 조건

아래 P0 항목은 모두 통과해야 릴리스할 수 있다. P1은 해당 플랫폼 지원 릴리스의 출하 조건이다.

| ID | 우선순위 | 시나리오 | 기대 결과 |
| --- | --- | --- | --- |
| IMG-01 | P0 | Windows, macOS, Linux에서 스크린샷을 복사해 다른 지원 OS에 붙여넣기 | 이미지가 비어 있지 않고 원본 크기·투명도·색상이 보존된다. |
| IMG-02 | P0 | 손상된 PNG, 초과 크기, 순서가 틀린 청크 수신 | 수신 클립보드는 바뀌지 않고 오류가 기록된다. |
| NET-01 | P0 | 연결된 클라이언트의 Wi-Fi를 끄고 다시 켜기 | 30초 이내 재연결하며 중복 연결·재시도 타이머가 없다. |
| NET-02 | P0 | 서버 프로세스를 재시작 | 클라이언트가 저장된 주소로 자동 재연결하고 입력 공유가 복구된다. |
| NET-03 | P0 | 절전 후 복귀 | 한 번의 연결 상태 전이 뒤 자동 복구한다. |
| XFER-01 | P0 | 1 GiB 파일을 화면 경계로 Windows↔macOS 전송 | 대상 활성 앱이 파일을 드롭으로 받고 SHA-256이 원본과 같다. |
| XFER-02 | P0 | 중첩 폴더를 화면 경계로 전송 | 파일명과 상대 구조가 보존되고 대상 앱에 하나의 폴더 드롭으로 전달된다. |
| XFER-03 | P0 | 전송 중 25%, 50%, 75%에서 연결 끊기 | 재연결 뒤 마지막 ACK 오프셋부터 재개하며 완료 파일 해시가 일치한다. |
| XFER-04 | P0 | `../`, 절대 경로, 예약 장치 이름을 포함한 매니페스트 | 전송을 거부하고 수신 디렉터리 밖에 파일을 만들지 않는다. |
| XFER-05 | P0 | 디스크 공간 부족 또는 SHA-256 불일치 | 부분 데이터를 제거하고 GUI에 실패 이유를 한 번 표시한다. |
| GUI-01 | P0 | 연결·재연결·전송·오류 상태 전환 | 상태 문구, 아이콘, 시작/중지 동작이 실제 상태와 일치한다. |
| GUI-02 | P0 | TLS를 끈 상태에서 연결 | 연결 상태와 함께 지속적인 비암호화 경고가 표시된다. |
| GUI-03 | P1 | 키보드만으로 기본 화면 탐색 | 시작/중지, 기기 배치, 전송 보기가 탭 순서와 접근 가능한 이름을 가진다. |
| DND-01 | P1 | Windows와 macOS의 파일 관리자·브라우저·편집기 대상 드롭 | 각 앱이 표준 드롭처럼 파일을 수신한다. |
