# CapyBarrier 안정성·전송 기능 설계

## 목표

CapyBarrier는 기존 Barrier의 키보드·마우스 공유를 유지하면서, 새 CapyBarrier 노드 간에 안정적인 스크린샷 이미지 클립보드 공유, 화면 경계 기반 파일·폴더 드래그앤드롭, 자동 재연결을 제공한다.

## 확정된 제품 결정

- 모든 연결 기기는 이 기능을 포함한 같은 새 CapyBarrier 릴리스여야 한다. 원본 Barrier와 구버전 CapyBarrier는 프로토콜 핸드셰이크에서 거부한다.
- 이미지 우선 시나리오는 Windows·macOS·Linux에서 OS 스크린샷 도구로 복사한 이미지를 다른 기기에 붙여넣는 것이다.
- 파일과 폴더는 화면 경계를 넘어 대상 기기의 현재 활성 앱에 실제 드롭된다. 동작은 항상 **복사**다.
- 드래그앤드롭은 Windows와 macOS를 첫 지원 대상으로 하고, Linux X11과 Wayland는 각각 별도 후속 릴리스다.
- 전송 중 연결이 끊기면 자동 재연결 후 검증된 오프셋부터 재개한다.
- 클라이언트는 저장된 IP/호스트명만 사용해 자동 재연결한다. Bonjour 재발견·NAT 통과·인터넷 중계는 범위 밖이다.
- TLS는 기본 권장값이다. 사용자가 끄면 연결·전송은 허용하되 GUI는 지속 경고를 표시한다.
- GUI는 차분한 상태 중심의 데스크톱 유틸리티 스타일이다. 기본 화면은 상태·시작/중지·기기 배치만 제공한다.

## 아키텍처

### 프로토콜과 호환성

`protocol_types.h`의 프로토콜 메이저를 올리고, `ClientProxyUnknown`과 `Client::handleHello()`가 새 메이저만 수락한다. 연결 직후 양방향 `Capabilities` 메시지로 `clipboard-image-v2`, `transfer-v2`, `transfer-resume-v2`를 교환한다. 필요한 capability가 없으면 연결을 종료하며, 입력 이벤트를 보내기 전에 협상이 끝나야 한다.

전송은 기존 `DFTR`/`DDRG`와 `FileChunk`를 확장하지 않는다. 이 구현은 전체 파일을 `std::string`에 쌓고 static 수신 상태를 공유하므로 대용량, 여러 전송, 재개를 안전하게 처리할 수 없다. 새 `TransferSession`은 한 연결에서 하나의 활성 드롭을 관리하고, 모든 디스크 쓰기는 임시 경로에서 스트리밍한다.

### 전송 세션

드래그 시작 시 송신자는 상대 화면 이름, 항목 목록, 상대 경로, 유형(파일/디렉터리), 파일 크기, SHA-256을 포함한 매니페스트를 보낸다. 수신자는 각 상대 경로에 대해 절대 경로, `..`, 빈 세그먼트, 플랫폼 예약 이름을 거부하고 임시 수신 디렉터리를 생성한다.

수신자가 `TransferAccept(transferId, resumeOffsets)`를 보내면 송신자는 파일별로 정해진 청크 크기의 데이터를 보낸다. 수신자는 디스크에 순차 기록하고 파일별 확인 오프셋을 ACK한다. 재연결 뒤 같은 `transferId`와 매니페스트 해시를 제시하면 수신자가 마지막 검증 오프셋을 반환한다. 파일 SHA-256과 모든 항목 수가 일치할 때만 임시 디렉터리를 네이티브 드롭 공급자에 공개한다. 취소, 해시 불일치, 경로 거부, 저장 공간 부족은 임시 데이터를 정리하고 하나의 실패 상태로 끝낸다.

입력 메시지는 전송 ACK 대기 때문에 멈추지 않는다. 청크를 이벤트 큐에 순서대로 등록하고 매 청크 뒤 입력 이벤트가 처리될 기회를 준다.

### 이미지 클립보드

클립보드 전송은 이미지 payload와 format을 명시적으로 보존한다. 플랫폼 어댑터는 스크린샷 이미지를 표준 PNG 바이트로 정규화해 전송하고, 수신 플랫폼은 PNG와 해당 플랫폼이 요구하는 기본 비트맵 표현을 모두 클립보드에 게시한다. PNG 디코드 실패, 허용 크기 초과, 청크 순서 오류는 기존 클립보드를 지우지 않고 전송만 실패시킨다.

### 연결 복구

`Client`는 연결 실패·소켓 해제·절전 복귀에서 단일 재시도 타이머를 소유한다. 재시도 간격은 1, 2, 4, 8, 16, 30초로 제한하고 핸드셰이크 성공 뒤 1초로 초기화한다. 동시에 둘 이상의 연결 시도나 재시도 타이머가 존재해서는 안 된다. 복구 뒤 capability 협상과 보안 상태를 다시 적용하고, 중단된 전송만 재개한다.

### GUI

`MainWindow`의 상태 모델은 `Disconnected`, `Connecting`, `Connected`, `Reconnecting`, `Transferring`, `Error`를 구분한다. 메인 화면은 연결 수와 현재 역할, TLS 상태, 이미지 클립보드와 파일 전송의 짧은 상태, 전송 중 진행률, `시작/중지`·`기기 배치`·`전송 보기`만 표시한다.

로그·인증서 전체 지문·고급 설정은 보조 화면에 남긴다. 상태는 중립 표면과 절제된 녹색을 사용하고, 경고와 오류만 강조색을 쓴다. 모든 색상 정보에는 문구와 아이콘을 함께 제공한다.

## 범위 밖

- 원격 인터넷 연결, NAT 통과, 클라우드 중계, 계정 기반 기기 관리.
- Linux Wayland 지원을 Windows/macOS 첫 릴리스에 포함하는 일.
- 전송 완료 후 대상 앱 대신 Downloads 폴더에 파일을 보관하는 대체 흐름.
